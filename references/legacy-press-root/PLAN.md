# Plan

## 当前阶段

项目已经从“原型探索”进入“主流程收口与真实流稳定化”阶段。

当前主流程目标不是继续扩张页面，而是把真实项目路径稳定住：

1. 识别
2. 添加书籍信息
3. 文字和格式校对
4. 导出

## 已完成

- FastAPI 后端接管真实 API
- 浏览器模式支持真实 PDF 上传
- 上传后立即进入识别页
- 识别任务改为异步状态流
- 元数据确认页接入真实项目数据
- 校对页接入真实工作区与真实块保存
- PDF 预览接口改为 inline
- 校对页恢复 bbox 叠框
- 导出流程接入真实导出 API
- Electron dev runner 增加兼容后端探测

## 接下来优先级

### P0：验证真实项目 bbox 数据闭环

目标：

- 用新创建的真实项目验证 `preview.pages[].blocks[].bbox` 已稳定返回
- 确认真实校对页不只在 mock 数据下能看到 bbox

验收：

- 新项目识别完成后，校对页可看到 bbox 叠框
- 点击 bbox 能切换当前块

### P1：增强识别阶段反馈

目标：

- 让识别页不只显示 queued / processing / completed
- 提供更明确的阶段文案，最好带页数或子阶段

验收：

- 用户能理解识别是否真的在进行
- 失败时有清晰重试路径

### P1：把导出前检查继续收口

目标：

- 进一步降低“质量检查”作为独立页面的存在感
- 保持用户感知里只有“导出”这一步

验收：

- 用户从校对到导出的动作链更直接
- 不会误以为还有额外第五步

### P2：清理测试与旧文案

目标：

- 消除 `/projects//export` 这类非阻塞 warning
- 移除文档和 UI 里残留的旧表述

## 非当前重点

这些事现在不要抢主流程优先级：

- 大规模重构视觉主题
- 引入数据库
- 重新设计 schema
- 扩张新的导出格式
- 重新拆分大量页面

## 验收顺序

1. 真实浏览器流程
2. 真实 Electron 流程
3. 前端测试
4. 后端测试
