# WRX 微信读书修复补丁

仓库原有 `tools/content-pipeline` 是 WRX JSON 导入器，不包含浏览器插件本体。
这里维护用户本机 WRX 0.1.0.15 的可审查补丁；第三方库、混淆后的页面覆盖脚本、图片等
仍由原插件提供，不复制进仓库。

```powershell
node tools/weread-extension/apply.mjs "C:\Users\YOUR_NAME\Downloads\wrx-v0.1.0.6"
pnpm --filter @jojo/weread-extension test
```

应用前会在插件目录旁备份已有的修改文件和 manifest。
补丁更新为 0.1.0.18，保留原权限、站点覆盖规则及旧缓存原始记录。
在浏览器扩展管理页面重新加载 WRX，再刷新微信读书书页才会生效。

0.1.0.18 将翻章完成状态和导出按钮的绿色绑定到完整缓存，完成后停止、点击导出或刷新
书页都能保留绿色提示；不改变采集、缓存和导出内容。

0.1.0.17 针对大书连续翻章时的内存峰值增加了这些处理：

- IndexedDB 升级为 v3，增加逐章完成状态和迁移标记。普通书页启动只读取小型状态记录，
  不再读取整本旧缓存或扫描全部正文。首次升级在独立 Worker 中整理旧记录，保留原记录，
  完成后不重复整理；中断后可重试，已有 v2 新分片优先于旧分片。
- 导出在 Worker 中逐章序列化为 Blob，再组合为文件。书页主线程不接收完整正文数组，
  不执行整本 `JSON.stringify`；返回 Blob 后即可关闭 Worker。
- 每个页面至多加载 8 个未缓存章节后重载续传。若 Chrome 可用的 JS 堆指标超过
  384 MiB 或堆上限的 40%，则在保存完当前章后提前重载；不依赖堆指标也会按章数重载。
  自动导航使用 `location.replace`，避免不断增加历史页面。
- 目录 CID 和标题索引只在 TOC 更新时计算，目录标记监听限定为目录相关变动。

旧缓存整理与导出使用同源 Blob Worker；如果浏览器阻止 Worker，会明确停止并保留数据，
不会退回主线程加载整本书。数据库升到 v3 后，不应直接恢复只支持 v2 的旧版脚本。

修复内容：

- 不再依赖宽泛的页尾按钮选择器。按完整目录选取缺失章节，通过目录点击跳转；目录未挂载、
  标题重复或点击无响应时使用阅读页章节链接，并在刷新后继续。正向/反向表示补全顺序。
- 进度取自 IndexedDB，按唯一 CID 统计。EPUB 收齐 `e_0/e_1/e_3` 或 TXT 收齐 `t_0/t_1`，
  且写入事务完成才算缓存成功；HTTP 错误、JSON 错误响应、预取别章、目录关闭均不算成功。
- 跳过已完整缓存章节，以目标章节落盘为继续条件，不固定等 UI 切换后的 0.9 秒。
  目录和章节等待均有上限，停止操作使旧任务失效，页面重载续传状态两分钟过期。
- 网络监听在 MAIN world 的 `document_start` 安装，避免动态注入脚本晚于首批正文请求。
  fetch 正确读取 Request/RequestInit 的请求体，仅复制命中的响应，保留共享知乎监听能力。
- 缓存恢复读取逐章状态；目录重绘后恢复标记，不再按搜索结果索引绑定 CID。
  严格检查目录数量和所需章节分片后才允许导出，兼容两种元数据结构。

速度取决于页面响应和本机缓存；补丁不会并发请求正文。现有站点覆盖脚本是否仍适配当前
微信读书版本，需在已登录的实际浏览器中验证。源码回归测试不能替代这一步。
